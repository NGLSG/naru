# C11 压力测试

C11 方言的验收目标是编译未经改写的真实 C11 项目，使用目标系统的
C 标准库。当前实现尚未达到这个目标，不能用于宣称完整 C11 兼容。
语言规则位于 `dialects/c11/`；Naru 核心不识别 C 关键字或预处理指令。
标准语义以 [WG14 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
为检查依据，平台扩展属于单独的 C 规则模块。

2026-10-12 方言调试修复了条件表达式的指针类型、限定符合并、聚合/void
分支以及字符串 sizeof。函数地址与 void* 的宿主互转现需显式组合
`dialects/c11/function-pointer-interop.stx`；标准 NULL 路径无需该扩展。
第二轮把指针上下文与共享常量求值器接通：整数运算、枚举、固定对象
sizeof、整数条件表达式的零值在初始化/赋值/参数/返回/比较等位置保持
一致；普通变量、const 对象及带赋值副作用的运行时零值仍被拒绝。
后续完整支持工作使用 [逐条覆盖清单与工程验收](c11-conformance.md) 跟踪，
不能从小型压力测试的通过数换算标准覆盖率。
复现、回归与剩余范围见 [方言调试记录](dialect-debug.md)。

## 系统头文件和运行库

方言通过 `target.toolchain(configuration)` 获取实际目标事实及已安装的
SDK 搜索路径。头文件和原生链接共享同一个进程内发现实现；Windows 上
使用 LLVM 的 MSVC/Windows SDK 发现 API，不启动 `vswhere` 或编译器进程。
显式 SDK 根目录或版本无效时报告错误，不静默切换到其他目录。

`dialects/headers.stx` 实现可复用的头文件搜索：带引号的 include 先搜索
当前文件目录，再搜索项目配置和系统目录；尖括号 include 不搜索当前目录。
`source.read` 读取的依赖参与输出覆盖保护。原有手写替代标准头文件已删除，
没有项目内的标准头文件后备路径。系统库继续通过进程内 LLD 链接。

当前 C 类型和 ABI 规则只支持 Windows x86_64 的 LLP64 配置，其他目标
会明确报错。目标发现原语本身与 C 无关；新语言可以使用相同的目标事实。
动态 CRT 的头文件宏配置、其他平台的 C ABI 和完整系统头文件兼容仍待实现。

## 已提取的规则基础设施

- 不可变链表共享 tail；prepend 为常数时间，concat 只复制左侧边，
  `list.flatten` 一次合并多个块。预处理输出以块累积，避免不断复制全部输出。
- `env` 使用持久化压缩哈希树，支持结构化键、哈希碰撞和保留旧版本。
- 动态 effect 在词法捕获帧中求值，避免每次调用复制完整规则正文。
- 规则回调在嵌套分配作用域中执行，回收没有从结果或 IR 副作用逃逸的
  新节点、共享边和环境索引。追踪使用迭代工作队列，按嵌套深度复用缓冲区；
  借入值、共享列表/cursor、持久环境旧版本和 IR 的身份保持稳定。
  回调外的求值与解析临时值仍属于编译 arena，尚未实行全局垃圾回收。
- `env.entries(environment)` 枚举最新的唯一键值对；所有权 join 和记录
  校验通过这个接口遍历，解除对私有环境父链的依赖。枚举不承诺插入顺序。
- 环境只保留持久哈希树根，不再强制保留全部更新历史；碰撞更新复制
  匹配路径，不积累重复键。effect 索引和入口关系解析结果在规则图不变时复用。
- effect 按参数数目和首参数的原子/构造器/列表形状筛选候选，仍合并所有
  通配候选并保持原始顺序；重载、守卫、fallback 和冲突诊断继续生效。
- `layout.sequential/overlap` 组合 `[大小, 对齐]` 事实，返回对象大小、对齐
  和成员偏移；普通 CPU 对齐使用整除快路径，其他对齐使用最小公倍数。
  该库不包含 C 类型或关键字，可供独立设备方言使用。
- `tree.fold` 使用显式工作列表；`tree.fold_with` 让调用方定义子节点策略，
  可在嵌套作用域处停止遍历。`cfg` 提供标签预声明、跳转、不可达后继
  和整数分派，C 的 `switch/goto` 通过这些共享规则生成 CFG。
- `tree.rewrite_with` 提供进入/退出回调、剪枝、子上下文和从左到右的状态传递。
  聚合完成、字符串池和静态局部提升使用这个显式栈；未知构造器保持原样。
  `term.children` 共享不可变子节点边，`term.rebuild` 保留源码位置并复用未变化节点。
  `rule.iterate` 按存活状态大小调整临时对象回收间隔，避免保存全部历史状态。
- 解析器缓存类别、位置、优先级和不可变上下文对应的解析结果，保留冲突诊断。
- 前端可把 token 标记为 kind 14 的原子终结符，用 quoted terminal 或
  普通标点匹配；它不会被拆开，也不能被当作 identifier/string 捕获。
  这使 `++x` 和 `+ +x` 保持不同词法边界，无需给核心增加 C 运算符表。
- `syntax ... when predicate => expression` 支持纯语法守卫。
  `syntax.context()` 提供当前解析上下文；守卫禁止 IO、IR 和新身份创建。
- `source.parse_tokens(tokens, category, context, commitRelation)` 只在选定
  唯一语法结果后调用提交关系。提交返回 `[newContext, itemList]`，失败候选
  不提交上下文。原两参数接口仍然有效。
- `--rule-budget`、`--parse-budget` 和项目 `[limits]` 提供有限的执行步数配置；
  `--rule-depth`、`--parse-depth` 独立配置 1..1024 的递归深度，默认 256。
  所有解析接口的守卫和消歧回调共享调用方剩余求值预算，候选匹配也计入解析预算。
- 原始前端可显式指定纯消歧关系；`rule.select` 提供可组合的词典序排名，
  `parse.specific` 提供字面量优先策略。未配置策略和最高排名相同仍报告冲突。
  当前接口处理同跨度候选，不是任意二义文法的广义解析森林。
- `text.lines/line_spans/columns/expand_tabs` 提供一次行扫描、原始字节跨度、
  字节或 UTF-8 码点列及制表符展开，可组合实现固定列语言前端。

这些能力没有引入 C 专用的核心类型。C 顶层 typedef 通过上下文提交成为
之后的类型语法候选；块作用域、参数作用域的规则扩展见
[作用域实现记录](c11-scopes.md)，完整名字空间与声明约束仍需继续验证。
冻结编译器也序列化语法守卫并调用同样的提交协议。

## 真实项目验收

```powershell
python tests/c11_stress.py
.\test.ps1 -C11Stress
```

压力测试包括系统分配/字符串/stdio、多翻译单元、函数指针声明、递归聚合和指定初始化、
enum/switch/goto、泛型选择、varargs、对齐和布局，以及两个固定版本项目：

- [TinyExpr](https://github.com/codeplea/tinyexpr)，提交
  `7ab30db449a359e8af77fbb062ab2ec7ee686d62`。
- [cJSON](https://github.com/DaveGamble/cJSON)，提交
  `6d9f2443ab071f86e5d9b43025a40929ec41c46c`。

上游源文件不改写；`tests/c11/projects/sources.json` 固定下载地址、提交和
SHA256，并保留各自许可证。另写的小型 main 驱动负责检查结果和资源释放。
参考 Clang 独立编译并执行这些输入，以排除夹具自身错误；参考对象从不交给
Naru。Naru 的每个翻译单元均由选定的 STX 方言处理，再由原生后端发射和链接。

测试在 PATH 为空、只允许一个进程的 Windows Job 内运行 Naru，默认给编译
设置 60 秒和 2 GiB 私有提交内存上限。报告保存编译时间、峰值私有提交内存、
诊断、原生退出值及输出。失败、崩溃、超时和缺失功能均计为失败，没有将已知
缺陷改为预期成功的路径。单次完整报告在 `target/c11-stress.json`；选择部分
case 不会把报告标记为完整套件通过。这个小套件也不等于完整标准一致性认证。

`tests/frontend_infra.py` 独立验证上述共享基础设施，不把 C11 失败计入共享
设施的通过数。常规 `test.ps1` 运行此回归；`-C11Stress` 增加尚待完成的
C11 验收门槛，`-FrontendAot` 构建并检查冻结版本的同一组共享设施。
列表/环境微基准测量的是编译器前端设施，不是生成程序的运行时性能。

2026-10-11 的 `target/c11-stress-current.json` 为 12/12 通过，包含未经
改写的 TinyExpr 和 cJSON；此报告只证明固定输入的编译和运行结果。
编译峰值内存仍约 1 GiB，解析、语义检查及降低阶段仍有进一步优化空间。

2026-10-12 在新作用域、常量与联合体规则下重新验收仍为 12/12。
报告现在保存实际编译器、同目录后端、规则、夹具及上游源码 SHA-256，
并验证运行前后输入没有变化。本轮显式使用 1536 MiB 编译内存限制：
cJSON 的翻译单元峰值约 1275 MiB，两翻译单元累计编译约 29.5 秒；
TinyExpr 峰值约 1150 MiB、累计约 24.5 秒。这是编译开销，并非程序运行时
性能；该规模还不足以推断 GCC 源码构建的内存与时间。

## 声明器与静态对象

`c11.declarators` 把指针、数组和函数后缀组成声明器，再从外向内应用到
共享的声明说明符。`int *a, b` 的 b 保持 int；`int *f(void)` 与
`int (*f)(void)` 得到不同类型。参数数组/函数声明器调整成指针，支持
括号绑定、抽象声明器、逗号声明和 typedef 组，以及间接调用和函数地址。
`static` 函数/对象使用内部链接，静态局部对象在模块准备阶段提升为
独立的内部全局，初始化只发生一次。
带初始化的无界数组从元素数量或最大指定下标推导边界；复合字面量复用相同规则。
嵌套静态表可以组合字符串地址、函数地址和空指针常量。限定的数组成员衰减时
把限定符传给元素；指针步进在语义环境中完成命名聚合的布局。
MSVC `i64/Ui64/i64U` 后缀映射到共享的精确整数候选规则，使用实际 SDK 的常量。
普通声明的名字在初始化器之前进入作用域，参数复制通过独立规则读取传入的 SSA 值。

C 函数声明和定义统一使用 `llvm.func` / `llvm.call`，包括可变参数；
参数绑定、局部存储规划和 CFG 仍复用 `base.function_region`，返回指令
由函数环境中的策略事实选择。安装的 MSVC `stdarg.h` / `vadefs.h` 不改写：
`__va_start` 由目标方言发射 `llvm.intr.vastart`，`va_arg`、`va_end` 和
`va_copy` 使用系统头文件自身的宏。已验证整数跨寄存器/栈传递、float/char
默认提升、独立复制游标及间接可变参数调用。其他平台的 va_list ABI 尚未实现。
MSVC `__inline` 定义使用 `linkonce_odr` 和 COMDAT 去重，使系统 stdio 的
包装函数可以与实际 CRT 链接。它的静态局部对象也具有稳定名称和独立
COMDAT，跨翻译单元共享同一对象；`noinline` 注解保留为 LLVM 属性。
标准 C inline 的全部跨翻译单元约束仍待补齐。

`_Generic` 的控制表达式只分析、不执行。各关联表达式都会经过类型检查，
仅选择的关联进入运行时 IR。重复关联和重复 default 会报告错误。

`tests/c11_declarations.py` 验证这些组合的原生结果和拒绝诊断，还包含
1500 个全局声明的翻译单元。模块改写、声明收集和准备已改为迭代遍历；
宏替换、字符串化和数组初始化使用 prepend/reverse/join，消除增长前缀
反复复制产生的二次复杂度。

`tests/frontend_perf.py --baseline <旧版 naru.exe>` 对两个编译器使用完全
相同的当前规则文件与输入，确认结果相等，分别记录时间与峰值提交内存。
它测量编译器前端，不代表生成程序的运行时性能；普通小型输入可能承担
索引和生命周期追踪的固定成本。

`tests/tree_perf.py --baseline <旧版 naru.exe>` 使用相同规则和输入，交替
测量宽构造器改写、深树改写和反复替换临时列表。默认三次，记录完整样本、
中位时间、峰值内存及编译器/规则哈希；无 baseline 时作为常规正确性回归运行。
`target/tree-performance-current.json` 对回收前后版本使用相同规则测量三轮：
宽节点、深树及替换临时列表的峰值内存分别下降约 60%、35%、66%。
中位时间比为 0.993、1.021、1.042，本次主要改善内存，未证明编译加速。

## 聚合、枚举与控制流

结构体和联合体使用同一套布局事实。联合体成员共享存储，LLVM 表示使用
与目标自然对齐匹配的整数单元；成员寻址使用源类型的字节偏移。匿名
结构体/联合体的成员按嵌套偏移提升，重复成员名会被拒绝。柔性数组使用
零元素 LLVM 数组保留其对齐和偏移，结构体尾部补齐不改变成员地址；
`sizeof` 不接受柔性数组本身，也不会让普通数组成员先衰减成指针。

`c11.union_storage` 通过共享标量片段窗口转换对象表示，源表达式只降低
一次。自然对齐的对象/函数地址、多个地址以及嵌套聚合的重定位可以完整
保存在整数槽位中，避免整对象大整数拼接。共享 LLVM 翻译防护另保证无法
生成常量的初始化操作给出诊断，清理时不因符号用户未释放而崩溃。

标签定义收集后全部验证，包括未被使用的定义和匿名 typedef。完成的
命名类型缓存在持久环境中，后续引用共享描述符，指针允许递归标签。
当前标签作用域尚未完整区分块与函数，因此合法的局部标签遮蔽仍有限制。

顶层枚举支持显式/隐式值、之前的枚举常量、整数常量运算及数组界限。
枚举常量参与普通标识符空间，运行时对象可按块作用域遮蔽它们。此目标
选择 int 存储并要求枚举常量可表示为 int。局部枚举定义、嵌套说明符中
的常量安装以及 enum 与兼容整数类型的全部类型兼容规则仍待补齐。

`for` 的初始化、条件和迭代子句通过独立类别组合，支持空子句和逗号
序列表达式。`switch` 保留单次选择器求值、共享 case、贯穿执行及嵌套
switch 的独立分派；case 转换后重复、重复 default 和作用域外的标签
会被拒绝。`break` 使用最近的循环/switch 出口，`continue` 使用循环
入口；for 的迭代子句在 continue 时仍执行。函数标签支持前向/后向
goto，return 后或两分支均 return 后的标签也会保留。分派生成真正的
`cf.switch`，继续由 MLIR/LLVM 优化流水线处理。

`__declspec(dllexport/dllimport)` 作为独立符号事实保留，与 noinline、
调用约定、链接属性按包装层逐层组合。后端在 LLVM 优化之前应用通用
`naru.llvm.dll_storage_class` 属性；COFF 输出包含导出指令。导入定义、
内部导出、相互冲突的声明和非 Windows 目标会被拒绝。

`tests/c11_composition.py` 使用独立 Clang 结果校验 O0/O2 原生程序，
并检查拒绝诊断和失败产物保护。`tests/rule_tools.py` 单独验证共享布局、
遍历和 CFG 工具；冻结版本运行相同检查，无需读取规则文件。

## 当前仍需补齐

声明器的完整存储类/限定符排列、无原型函数与旧式定义、完整作用域
及名字空间遮蔽、标准 inline 链接约束、系统 SDK 扩展、初始化器省略花括号、
复合字面量的完整存储期规则、全部地址常量形式和链式指定初始化、完整 enum/union
约束、bitfield、控制流的完整约束、字符和宽字符、对齐及聚合 ABI
都需要继续实现和验证。源变换也还需要保留三字符序列替换及续行拼接后的
物理位置映射。可选的 VLA、原子、线程和复数能力需要明确的目标策略及
符合该策略的系统库接口。真实项目压力报告是当前能力的证据；基础用例
通过不代表完整 C11 已经实现。

## 位运算复合赋值与 SDK 注解

`&= / ^= / |= / <<= / >>=` 复用 C 的整数提升、移位规则、对象引用和
存储转换。复合赋值的左值地址只求值一次；`a[i++]` 的下标按完整表达式
类别解析，支持副作用和逗号表达式。const 左值和浮点移位在语义阶段拒绝。

`c11.msvc.tokens` 在预处理之后以一次 token fold 处理
`__pragma(warning(...))`，包括实际系统 `math.h` 的表达式宏。
警告注解不改变生成程序；其他 pragma 保留原始 token，pack 的已有校验仍生效。
未结束的 warning pragma 明确报错。cJSON 能越过该 SDK 宏，但后续剩余
扩展语法仍需要独立覆盖测试。

基础类型声明改为“类型词列表 → 计数事实 → 约束校验 → 类型描述符”的规则组合，
支持 `long unsigned int`、`int short unsigned`、`double long` 等排列，
不再为每种排列添加独立语法。重复类型词、冲突符号和非法整数/浮点组合会报错。
类型限定符与存储类在所有位置的任意交错仍未完全覆盖。
