# C11 方言

C11 的语法、预处理和语义位于 `dialects/c11/`，以 [WG14 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) 为基准。当前目标为 Windows x86_64、MSVC/UCRT LLP64；标准库使用安装的系统头文件、编译器资源头和 CRT。

完整兼容性仍在验证，当前失败见 [实现状态](status.md)，测试方法见 [conformance](c11-conformance.md)。

## 编译项目

```powershell
.\target\naru.exe resolve --project examples\c11
.\target\naru.exe build --project examples\c11 --locked
```

`examples/c11/Naru.toml` 选择 C11 方言、`main.c` 入口及链接配置。其他项目同样通过配置选择前端，不要求 `.nru` 扩展名。外部对象、库和 CRT 模式见 [项目与链接](projects.md)。

表中列出已接入的规则，专项验证进度由 [全量支持计划](c11-full-support.md) 跟踪。

声明说明符先收集为事实，再按组合约束归一化，无需逐一枚举关键字排列。名字和类型保留声明点快照，后续声明不能反向修改先前表达式的可见类型。

初始化共用 current-object 遍历，处理花括号省略、指定链、覆盖和数组边界推断。自动复合字面量按语法站点规划帧存储，每次执行时初始化；文件作用域字面量使用静态对象。

## 系统头与目标策略

`target.toolchain(configuration)` 通过进程内 API 发现 MSVC/Windows SDK。`headers` 规则库负责搜索，带引号的 include 先查当前目录，再查项目和系统目录；尖括号 include 跳过当前目录。资源头来源由目标策略选择，详见 [库接口契约](c11-library-contract.md)。

`c11.system_headers`、`c11.msvc` 和 `c11.gnu_attributes` 处理实际头文件要求的目标接口。函数使用 `llvm.func` / `llvm.call`，变参宏来自系统 `stdarg.h`。系统库由进程内 LLD 链接。

TinyExpr 使用函数指针与 `void*` 互转扩展，压力测试显式加载 `function-pointer-interop.stx`。默认 C11 规则保留相应约束。

## 可复用设施

C 语言规则使用以下共享库，其他语言可独立选用：

| 设施 | 用途 |
| --- | --- |
| `headers`、`source`、`text` | 文件搜索、上下文解析、固定列和行处理 |
| `name_scope`、`env` | 不可变作用域、绑定身份与声明点快照 |
| `tree`、`pipeline` | 显式栈遍历、上下文改写和阶段排序 |
| `layout`、`storage` | 对齐、偏移、对象窗口及静态镜像 |
| `allocation`、`stack_regions`、`cfg` | 分配站点、动态栈生命周期和控制流 |
| `floating`、`complex_numbers`、`ir_effects` | 浮点策略、复数算法和有序 IR 区域 |

## 真实项目测试

```powershell
python tests/c11_stress.py
.\test.ps1 -C11Stress
```

测试包含系统分配、字符串、stdio、多翻译单元、函数指针、聚合和控制流，以及两个固定版本的项目：

- [TinyExpr](https://github.com/codeplea/tinyexpr)，提交 `7ab30db449a359e8af77fbb062ab2ec7ee686d62`。
- [cJSON](https://github.com/DaveGamble/cJSON)，提交 `6d9f2443ab071f86e5d9b43025a40929ec41c46c`。

`tests/c11/projects/sources.json` 保存来源和哈希。上游源码保持原样，测试驱动负责检查结果及资源释放。默认每次编译限制 60 秒、2 GiB 私有提交内存，报告写入 `target/c11-stress.json`。
